# Domain docs

## Before exploring

Read the root CONTEXT.md and relevant decisions in docs/adr/.
If these are absent, proceed silently. The domain-modeling skill
creates them when domain terms or decisions are resolved.

## Layout

This repo uses a single context:
- CONTEXT.md holds domain terminology.
- docs/adr/ holds architectural decisions.

## Vocabulary and decisions

Use the glossary's terms when naming domain concepts in issues,
proposals, hypotheses, and tests.

When a term is missing, reconsider the wording or note the gap
for domain-modeling.

If a proposal contradicts an ADR, identify the ADR and explain
why the decision should be reconsidered.
